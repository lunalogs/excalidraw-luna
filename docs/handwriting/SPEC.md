# 第二阶段完整要求与实施计划

版本：v1，2026-09-25。本文是待实现合同，不是已完成功能说明。

## 0. 目标与边界

用户要在 iPad 上自然写画：点画笔就在左上属性悬浮板调整笔触，保存常用预设，画线/圆/方形后按住停笔自动规整，并可通过文件导入导出继续编辑。所有笔刷计算、预设管理、图形识别在客户端进行；无需登录和外部 AI API。现有 Google Drive 等可选功能不作为前提，不擅自删除，也不把新笔画/预设自动上传到它们。

本期包含 M1–M5 网页实现；M6 原生 App 是后续独立阶段。本期不承诺系统级零误触、不做手写文字识别，不做像素级局部橡皮，不增加云存储服务。

## 2. UI 与交互（需求 UI-01–UI-08）

- **UI-01** 删除左下角“手写与文件”整个固定入口。选中顶部自由画笔后，在已有的左上属性悬浮板中显示笔刷设置。桌面完整属性模式和 iPad 紧凑属性模式都要接通，不能只实现其中之一。
- **UI-02** 面板依次为：笔触（画笔/钢笔/荧光笔）、预设选择、粗细/颜色/不透明度、四个高级参数、试写区、停笔规整开关与等待时间。高级区可折叠，常用设置应可直接操作。
- **UI-03** 选择其他工具时恢复该工具的属性面板。改笔刷参数默认只影响下一笔，不改已画内容、不清空画布、不创建历史记录；笔尖已经按下时锁定该笔参数快照，下笔中调整参数只影响下一笔。
- **UI-04** 橡皮提供一击切换和返回上一个笔触；保留宽度、颜色、高级参数、预设选择。整笔画/对象擦除和撤销继续可用，手指导航不擦除。
- **UI-05** 文件操作与笔刷解耦：在主菜单顶部常驻“打开文件 / 导入”“导出可编辑文件”，选中任何工具都可访问。复用文件选择、替换确认、内嵌图片准备、分享/下载降级；不新增第二套不兼容序列化。
- **UI-06** iPad 横屏/竖屏/分屏可用，面板不超出编辑器容器（不是只检查 window 尺寸）。短屏允许面板内部滚动，顶部工具栏仍可用，点击控件不落笔、不触发画布手势。主要按钮触控区域 >=44 CSS px。
- **UI-07** 有明确标签、键盘焦点、滑块当前值和恢复默认；中英文完整。禁用状态解释原因。不要在普通界面显示 API/桥接/内部实现说明，把硬件能力限制放到帮助中。
- **UI-08** 小型试写区使用与画布相同的笔刷渲染路径，可试写和清空，不进入文档、不污染撤销或本地文件。参数改变后固定示例笔迹同步更新，方便比较轻/重压与笔尖形状。

## 3. 笔刷参数的独立语义（BR-01–BR-09）

### 3.1 必须可调的参数

| 控件 | 范围与建议默认 | 明确含义 | 必须可见的差别 |
| --- | --- | --- | --- |
| 粗细 | 沿用 0.25–12，步进 0.25 | 现有 strokeWidth 的基础尺寸，不谎称是物理毫米 | 同压力下笔迹整体变粗/变细 |
| 按压力度（压感幅度） | 0–100，画笔 60/钢笔 85/荧光笔 0 | 压力改变宽度的幅度；0 为恒定宽度 | 同一组压力采样下，幅度越高轻重压宽差越大 |
| 笔尖灵敏度 | 0–100，默认 50 | 压力响应曲线，高灵敏度轻压即有较大响应 | 不改变输入路径；中低压响应可独立变化 |
| 笔尖扁平度 | 0–100，画笔 0/钢笔 40/荧光笔 70 | 椭圆/扁头笔尖短轴相对长轴压缩程度 | 高扁平度时不同方向的笔画宽度不同 |
| 笔尖角度 | 0–180°，默认 45° | 固定扁笔尖在画布坐标中的方向 | 扁平度 0 时禁用；旋转画笔方向后轮廓改变 |
| 画笔稳定性 | 0–100，默认 30 | 减小路径抖动，允许可控跟随延迟 | 0 接近原始路径，100 明显稳定，抬笔补齐末端 |
| 不透明度 | 1–100，画笔/钢笔 100、荧光笔 30 | 整笔透明度 | 荧光笔单笔内部不重复堆叠发黑；不同笔交叉正常叠色 |

这些默认值是第一版产品设定，调整需给出试写/设备证据并记录。荧光笔只是默认压感幅度 0，用户可以修改；不得让调节控件看似生效却被硬编码覆盖。

- **BR-01** 压力幅度与灵敏度独立。建议先将原始压力限制到 [0,1]，用 `pResponse = p ^ gamma`，`gamma = 2 ^ ((50 - sensitivity) / 25)`，再把压力响应与幅度组合进笔刷宽度。中性灵敏度 50 对应 gamma=1；幅度 0 下灵敏度不改变宽度。若采用其他模型，须保留语义并说明公式、极值与测试。
- **BR-02** `perfect-freehand` 已有 thinning/smoothing/streamline 等能力，优先复用锁定版本。不能仅把两个滑块都映射到 thinning；“稳定性”不能只是降低采样率。
- **BR-03** 扁平度必须是实际笔尖几何形变，不能冒用圆角、粗糙度、透明度。建议最小轴比约 0.15 以避免退化；固定方向椭圆笔尖的扫掠轮廓应连续。实现方案可用经过证明的局部坐标变换或自有轮廓算法，需验证转角、自交、点状笔迹和末端。不要整体缩放整条笔迹的中心线来伪装笔尖扁平度。
- **BR-04** 网页第一版用固定笔尖角度即可；真实 tilt/twist 随设备和浏览器能力可选，不是交付阻塞项，也不能把固定角度宣称为读取到硬件倾斜。
- **BR-05** 复用同一纯函数轮廓算法供静态画布、实时预览、试写、SVG/PNG 导出、命中/橡皮与边界计算使用；核查旋转、缩放和 ShapeCache 失效条件，避免屏幕与导出形状不同、宽笔被裁切或点不到边缘。
- **BR-06** 优先真实 `PointerEvent.pressure`，缺失时有明确的模拟压感降级。不要仅凭一次 pressure===0.5 判断没有压力，支持真实笔在 0.5 保持或从 0 开始。鼠标/手指可模拟压感，需测试点按、轻压、零值、NaN 和范围外输入。
- **BR-07** 如使用 `getCoalescedEvents()` 必须特性检测、保持时间顺序、去除主事件重复样本，不把另一 pointerId 混入当前笔画；缺少 API 仍能正常画。预测点只能用于临时预览，不可写入保存数据。位置未变但压力改变仍应被考虑。
- **BR-08** 稳定算法需与事件频率/刷新率解耦。强稳定下抬笔收敛到真实末端，不能截短、回弹、飞线。优先按帧更新预览，避免每个硬件样本都触发完整 React 树渲染，热路径不要每帧重算整张画布。
- **BR-09** 现有老笔画默认外观保持不变；对无新版参数的元素走旧算法分支，不能因为全局默认值变化让历史文件所有笔画变样。

## 4. 数据与个人预设（DATA-01–DATA-06 / PRE-01–PRE-06）

### 4.1 每条笔画的参数快照

**DATA-01** 引入有版本的笔刷配置类型，至少包含：schemaVersion、brushKind、pressureAmount、pressureSensitivity、nibFlatness、nibAngle、stabilization。宽度/颜色/透明度优先仍用既有 element 字段，避免两份来源互相矛盾。每条新笔画保存参数值快照，不能只保存 presetId；修改/删除预设不得改变旧笔画。

**DATA-02** 推荐保留 `customData.handwritingBrush` 老字段兼容，在 `customData.handwriting` 下存新版对象。要有集中 decode/normalize/validate 函数和 TypeScript 类型，合并其他 customData 键，不把整个 customData 覆盖掉。老 standard/fountain/highlighter 文件继续可读；未知版本安全降级、不崩溃、尽可能保留未知数据。

**DATA-03** 默认采用：element.points 保存完成稳定处理后的中心线，element.pressures 保存与之逐点对应的归一化原始压力，响应曲线由保存的参数在统一轮廓函数里应用。渲染/重载时不得再次对已稳定路径做稳定处理。若架构改用原始采样/处理后采样双轨，必须在记录中定义格式、空间成本、迁移和一致性策略。不要保存只有当前内存对象才能解释的闭包或缓存。

**DATA-04** 导入校验数值有限性、范围、字符串长度、数组规模和版本；处理缺字段/坏 JSON/未知 brushKind 不崩溃。导入中断、失败和撤销不得留下半完成笔迹。

**DATA-05** `.excalidraw` 导出包含所有笔迹所需参数、图片；在另一浏览器没有个人预设时仍保持外观。文件打开不能偷偷替换用户本地预设库。SVG/PNG 的轮廓和透明度必须一致。

**DATA-06** shape recognition 设置、用户当前笔刷、预设库分清持久化责任。识别计时器、预览候选、pointerId、性能缓存不导出，不进撤销，不进服务器状态。个人预设存本地，用独立 namespace 和 schemaVersion，存储损坏/满额要有恢复和反馈。

### 4.2 预设具体行为

- **PRE-01** 提供只读内置预设：画笔、钢笔、荧光笔。用户修改内置预设参数后显示“已修改”，可另存为个人预设。
- **PRE-02** 支持新增、命名、切换、更新当前自定义预设、复制、重命名、删除；至少可保存 12 个个人预设。名称去首尾空白，长度 1–40，重名给明确处理，不悄悄覆盖。
- **PRE-03** 切换预设恢复全套笔刷参数和颜色/宽度/透明度。未保存修改在切换时提示“保存 / 放弃 / 取消”。取消留在原状态。删除当前预设后回到内置默认，旧笔画不变。
- **PRE-04** 刷新、关页面重开保留个人预设和上次选择。无存储权限/空间不足时仍能画，明确告知未持久保存，不能显示假成功。
- **PRE-05** 增加预设 JSON 导入/导出（如 `.brush-presets.json`），允许用户通过文件界面备份到 iCloud/本地。格式具有 type、schemaVersion、presets。导入用预览/合并策略，ID 冲突重映射，名称冲突显示或自动加后缀；不修改现有文档和历史笔画。
- **PRE-06** 不把个人预设放进账户数据库、Supabase、Google Drive 自动同步或新增网络 API。用户明确导出/分享文件时才交给系统。

## 5. 停笔规整图形（SH-01–SH-12）

### 5.1 用户可预期的行为

- **SH-01** 画笔/钢笔提供“停笔规整”，默认开启；荧光笔默认关闭，可手动开启。按下画完后**笔尖仍接触屏幕并保持不动**才触发；抬笔后不启动计时器，也不在用户已开始下一笔后改旧笔画。
- **SH-02** 默认等待 **1.2 秒**，可调 0.5–3 秒，步进 0.1 秒。工具提示明确“画完后按住不动”。等待按最后有效移动开始计算，不是从 pointerdown 累计。
- **SH-03** 初始停留容差约 6 CSS px；按屏幕像素判断并换算场景坐标，缩放 25%、100%、400%时手感一致。以停留锚点/小窗口检测累计漂移，不能仅比较相邻点而允许缓慢漂走。压感变化本身不重置停留时间。
- **SH-04** 等待达到阈值且有高置信候选后，显示几何预览和低干扰提示，例如“直线 · 抬笔确认”。未达置信度就保留自由笔迹，不强制猜测。
- **SH-05** 预览期间继续移动超过容差，取消候选并继续原笔迹；重新停住可重新计时。Esc 取消本次候选并保留原笔迹。抬笔才提交规整；不能在候选切换时反复写入历史。
- **SH-06** 提交后短暂提供“恢复手绘”操作（约 5 秒）。恢复手绘替换同一条规整笔画，仍按正常历史事务可撤销；普通 Ctrl/Cmd+Z 撤销本次已提交笔迹，Redo 完整恢复。未转换绘画仍保持原有撤销语义。

### 5.2 本地识别与几何

- **SH-07** 首批识别直线、圆、椭圆、矩形、正方形，包括旋转矩形。输出原生可编辑 line/ellipse/rectangle 元素；线不能带箭头，闭合图形默认透明填充。图形继承颜色和不透明度；宽度折算需保持接近视觉粗细。原生几何不支持的变宽/扁笔尖效果以恒定描边表达，并在设计记录中说明。
- **SH-08** 本地确定性算法：路径去噪/按弧长等距重采样，直线最小二乘/PCA 残差，圆/椭圆拟合及覆盖度，矩形候选需闭合、四边覆盖、角点近直角及边方向一致。用相对笔迹尺度的残差作判定，处理短笔、点、绕多圈、回笔、多重折线和自交。
- **SH-09** 建议初始门槛（实现后用测试样本标定、记录最终数值）：屏幕包围盒对角线至少 24px；直线 RMS 误差/路径跨度<=0.04 且路径长度/端点距离<=1.15；闭合间隙/周长<=0.12；圆径向 RMS/半径<=0.08 并覆盖一整圈主要方向。椭圆/矩形需自己的残差与角度/覆盖检查，不能只靠包围盒。近圆的轴比>=0.9 可优先圆；近方形的边长比>=0.9 且矩形证据成立才优先正方形。候选得分含复杂度惩罚和差距阈值，模糊时宁可不转换。
- **SH-10** 圆保留拟合中心/大小，椭圆保留方向与轴长，矩形保留拟合旋转方向。直线默认保留用户方向，不默认吸到水平或垂直。正方形保留中心/方向并统一边长；不得突然远移、偏移到原点或丢失所属 frame/层级。
- **SH-11** 多指手势、切换工具、开始橡皮、pointercancel、丢失捕获、窗口失焦、页面隐藏、卸载时取消计时器和候选。手掌被过滤的 touch 不应打断正在接触的 Pencil 笔画；真正接管导航的多指手势必须取消规整。任何 timer 回调都校验当前 pointerId、strokeId 和交互代次，禁止修改上一笔。
- **SH-12** 样本集至少每类 10 条正例和 30 条负例（文字、锯齿、弧线、开放圆、点、多圈、星形等），固定随机种子。识别阈值不能按测试样本 ID 写分支。定时器用虚拟时钟，测试等待 1.2 秒不是真等 1.2 秒；实际手感另行真机测。

### 5.3 状态机建议

`idle → drawing → holding → preview → committed`

- drawing 中移动：记录笔迹，并重置停留锚点；静止进入 holding。
- holding 超时：对该笔快照识别；有合格候选才进入 preview。
- holding/preview 中有效移动：回 drawing 并撤候选，原采样不丢失。
- drawing/holding 抬笔：提交自由笔迹；preview 抬笔：一次原子提交几何。
- cancel/blur/tool-switch：清理 timer 与 preview，按现有中断绘画约定保留或结束原笔迹，不提交过期几何。

建议暂存候选叠层，不在识别预览期间污染 scene；转换时完整走既有 scene/history/binding API，不直接数组替换绕过索引、缓存或历史。

## 7. 性能与异常底线

- 目标 60Hz 交互；在实际测试设备记录帧耗时/输入延迟，而不是宣称所有 iPad 都 60fps。建议单帧 JS 预算 p95<8ms 作为优化目标，达不到时提供 profile 与降级方案。
- 1000 笔画、单笔 5000 采样的确定性样例，记录设备/浏览器、预览与识别耗时、内存趋势。几何识别只在停留时运行，对长笔迹做有上限的重采样（建议 128–256 点）。
- 导入/导出可以异步，但用户取消不丢原文档。断网可画、识别和保存本地；PWA 离线安装缓存属于已有能力，不把首次离线访问网页承诺为可用。
- 不新增付费 API、原生权限、后台上传、动态远端执行代码。新依赖须列用途、版本、许可证、体积和可替代方案。
