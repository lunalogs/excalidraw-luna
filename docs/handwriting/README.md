## 可以直接发给 Kimi 的任务

> 请在 `lunalogs/excalidraw-luna` 仓库的最新 `luna-design` 分支基础上工作，先阅读 AGENTS.md 和 docs/handwriting/ 下的全部交接文档。执行 SPEC.md 中的 M1–M5：把画笔设置迁入点击画笔后显示的左上属性悬浮板，实现独立的压力幅度、压力灵敏度、笔尖扁平度、画笔稳定性、可保存的个人预设，以及停笔按住后的本地几何规整。保留现有手写/橡皮/文件导入导出能力，不引入服务端图形识别或云存储。原生 iPad App 的 M6 仅作接口方案，不要把网页按钮或画布双击宣称为 Pencil 笔杆双击。
>
> 按里程碑分批实现，每批同步新增 docs/handwriting/changes/NNNN-主题.md，并更新 PROGRESS.md。任何代码、配置、依赖、测试、文档或后续修复都不能没有修改记录；记录要求见 CHANGELOG_TEMPLATE.md。每批列明需求 ID、变更文件、行为前后对比、真实执行的测试命令和结果、未通过项、截图/录屏位置、设计偏差及风险。未实测真机的项目标为“未验证”，不得写成通过。
>
> 工程基线从实际检出的提交读取并写进第一份记录，不猜测提交号。每个里程碑完成并检查后提交，遵循 AGENTS.md 的全量测试和类型检查要求，检查快照差异，不盲目接受更新。不要覆盖别人提交、强推或改动密钥。完成后给出工作分支、base/head SHA、提交列表、需求完成矩阵、剩余问题及一次性复现步骤，让 Codex 从该交付点 review。若缺少设备/凭据只阻塞对应原生或真机验收项，继续完成网页部分。

## 分工边界

- **Kimi**：实现与自测、完整修改记录、提供可复现的交付版本。
- **用户**：安排 Kimi 工作；需要时提供 iPad/Pencil 真机验收和原生签名环境，不把私人密钥写进仓库。
- **Codex**：收到代码/分支后检查实现、运行测试、核查真机证据、指出缺陷并修改；本轮不会代替 Kimi 实现第二阶段。

无需创建另一个 GitHub 项目，也不必购买图形识别 API。仓库中已使用 `perfect-freehand@1.2.0`，应先复用现有能力，依赖升级须说明必要性。
