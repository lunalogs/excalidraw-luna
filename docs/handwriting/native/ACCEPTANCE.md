# 原生混合文档验收与交付

状态：待实现验收合同。以[SPEC](SPEC.md)的N01–N21为准，旧网页ACCEPTANCE仍用于回归。

## A. 强制完整往返演示

用非私人fixture，在iPad写三行字、两条交叉荧光笔、一个被局部擦除的圆；放入文字、矩形、带绑定箭头与图片。保存到一个`.lunacanvas`文件。

电脑打开→圈第二行和矩形→一起移动、等比放大150%→整笔橡皮删掉一条笔迹→撤销/重做→导出文件。iPad重新打开：位置、大小、删除状态与电脑一致；第二行仍可原生局部擦除并继续写。再保存→电脑打开确认局部擦除结果。全过程无需登录或我们的服务器，不能用另存成整页PNG替代。

## C. 工程门槛

- 网页：全量Vitest（最终不更新快照）、tsc、全部改动及未跟踪源码的严格ESLint、构建、git diff --check；原AGENTS提交前检查继续适用。
- 原生：固定Xcode版本/部署目标、shared scheme、无签名模拟器构建、原生单元/集成测试。交付可复制的实际xcodebuild命令、destination与日志；真机签名由用户本地配置，不提交证书。
- 每个故障断言必须调用实际统一入口；不能仅测被绕过的底层类。读失败≠空文件，内存更新成功≠持久化成功。
- 自动快照差异逐项解释。针对几何与格式至少有一套独立期望值，不能用同一函数同时生成实际与期望。
- 真实fixture要附生成器、SDK/OS与源数据许可；禁止测试数据来自用户私人笔记。
