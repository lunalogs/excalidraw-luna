# 第三阶段：PencilKit 原生手写与跨端混合文档

状态：实施合同，尚未实现。2026-09-28。负责人：Kimi实现、自测；Codex复核；用户真机试写。

## 1. 已确认的产品决定

本阶段优先让iPad写字舒服，采用真正的原生PencilKit画布；只封装WKWebView、继续用网页freedraw不算完成。电脑继续使用现有网页，能整理原生手写内容，不需要原生写字或修改压感。

- **N01** 一个文档同时保存Excalidraw图形与PencilKit原始笔迹；本地/iCloud Drive文件往返，无新云存储、无登录前置。
- **N02** iPad：原生写画、笔/荧光笔等系统可用笔触、粗细/颜色、整笔与局部橡皮；Pencil写、单指移动、双指缩放。硬件双击按设备能力与系统偏好处理。
- **N03** 两端：圈选手写或图形，混合移动、等比放大缩小、删除、撤销重做。
- **N04** 电脑：橡皮删除碰到的整条笔迹、圈选后整段删除即可。**不要求电脑局部擦除，不要求切开笔画、重写笔迹或改原生笔触。**
- **N05** “圈出部分”按完整对象/完整笔画选择，不是把一笔沿圈边切断。画面缩放与所选内容缩放是两个独立操作。
- **N06** iPad→电脑整理→iPad继续写/擦的原生可编辑性必须保留。不能用图片覆盖原始数据。

本合同用于原SPEC.md的后续M6；原网页功能保留，原生流程按本文验收。原生手写不机械复刻网页压力曲线、灵敏度、扁平度、稳定性四滑块：先用系统真实能力获得手感；缺乏公开API的参数不显示假控件、不私用API。网页原参数与已有笔画仍保留。旧网页停笔规整保留；将其接入PencilKit是后续子项，不能声称PencilKit自动具备我们的形状规整或备忘录全部能力。

## 2. 架构与首先要验证的难点

推荐同仓库新增 `apps/ipad/` 原生工程（若实际结构冲突可调整并记录）：Swift/SwiftUI或UIKit + PKCanvasView，WKWebView复用现有Excalidraw图形编辑。网页静态资源打包进App，核心离线可用。不新增远端运行时依赖。

首批先完成最小原型与架构证据，不能一上来替换整个编辑器：

1. 真实PKCanvasView与系统工具选择器；写、擦、拖动画布、缩放、导出/重开。
2. 将3条原生笔迹输出为独立资源与预览；网页移动/缩放/删除其中一条后，回到PKCanvasView仍可局部擦除，且位置准确。
3. 荧光笔交叠预览与原生对照，不能因为逐笔PNG拼接改变混色而谎称无损。
4. 确定部署目标/SDK与公开API支持矩阵。不要依赖标注beta的PKStroke.id或新切笔API作为基础；自行维护稳定ID。

缺设备时可以继续文件协议、桥接和网页实现，但手感写“未验证”；不能用模拟器通过宣布原生阶段完成。

### 2.1 输入、图层与视口

- 原生PKCanvasView承担实时落墨，不能每个采样点经过JS桥往返。笔画结束/擦除事务结束后生成资源，重活异步处理，保存必须等待完整事务。
- 共用一个世界坐标和视口。明确scene point↔CSS px↔UIKit point↔像素的转换；DPR只影响栅格采样，不参与文档坐标。保存坐标不依赖设备尺寸。
- v1固定原生墨迹层在图形层之上；两端一致，不提供混合任意前后层排序。混合选择不改变层次。若以后需要图形夹在墨迹之间，另开设计，不用多个PKCanvasView仓促模拟。
- iPad区分“手写”和“整理”：手写时Pencil落墨、手指导航；整理时套索/选择手势操作统一对象。图形工具使用既有编辑器。一个触点只被一个输入层处理。
- 原生画布显示墨迹时关闭对应网页预览，避免重复显示；切换前后不能闪烁、消失或双重混色。
- 平移、缩放、旋转屏幕、分屏、失焦、取消、切后台期间不能产生幽灵笔画。手势冲突必须真机检查，不宣称pencilOnly本身自动完成所有导航要求。

## 3. 文件协议（N07–N12）

### 3.1 一个可携带文件

默认采用ZIP容器，扩展名 `.lunacanvas`，UTF-8 manifest，禁止伪装成原版`.excalidraw`。具体UTType和最终扩展名在首批固定。可以使用成熟ZIP依赖，需记录版本、许可证、包大小及使用理由。

建议布局（正式实现需提交TS/Swift类型、schema与fixture）：

```text
manifest.json
scene/excalidraw.json
ink/<asset-id>.drawing
previews/<asset-id>.png
hit/<asset-id>.json
files/<image-id>.<ext>
```

- manifest：type、schemaVersion、documentId、revision、必要能力、scene引用、inkObjects、资源表及哈希、显式层策略。
- 每个inkObject：稳定objectId、nativeAssetRef、previewRef、hitGeometryRef、局部renderBounds、统一世界变换、顺序、内容版本/哈希。资源只相对容器引用，禁止绝对路径或网络拉取。
- **N07** nativeAsset保存公开PKDrawing序列化结果。v1优先每个可独立选择笔画一个单笔PKDrawing资源；记录笔画mask/原始变换等，不自行猜测苹果二进制格式。
- **N08** 网页只能修改inkObject的变换、删除状态和顺序中允许的部分，原始drawing字节与哈希必须保留；预览可重建，原始笔迹不是可丢缓存。
- **N09** PKDrawing解码失败/未来墨水版本不支持时允许显示预览并完整保留资源，禁止自动转空、覆盖或伪称可编辑。未知主schema拒绝覆盖；可选扩展保留。
- **N10** 图片资源、笔迹原文、命中数据与预览必须一起保存；不能引用仅本机存在的路径。资源缺失报告并保持旧文档，不静默部分导入。
- **N11** 容器校验大小/条目数/解压总量/路径穿越/非有限坐标/无效引用/重复ID，记录明确限制。导入先完整校验再原子替换当前文档；失败保留旧文档和撤销历史。
- **N12** 不自动上传到现有Drive或其他连接服务。手写文档路径与服务器功能解耦，离线可用。

### 3.2 变换与身份

v1持久变换使用等比缩放+平移（可编码为6项仿射矩阵，禁止不支持的错切/负缩放进入写路径）；墨迹宽度随内容同比缩放。统一基准，原生资源是局部几何，worldTransform只应用一次。

电脑移动缩放不重写原生资源；iPad重建编辑画布时应用矩阵。若原生编辑结束将矩阵烘入新资源，必须事务性把对应变换归一，防止第二次打开重复缩放。原始mask与笔尖外观不可丢。

不得按数组下标或坐标哈希把笔画当永久ID。旧SDK无公开稳定ID时，需要适配层管理身份映射。局部橡皮可能修改/分裂笔迹：保留未变笔迹的ID，对修改/分裂结果分配明确新版本/子ID并记录替换关系。首批用重复形状、同点重画、删除前一笔再编辑后一笔证明映射正确；不依赖私有API或破解序列化。

### 3.3 预览与命中

- 预览由iPad用公开API生成；网页无需PencilKit解码。至少为目标缩放提供足够分辨率，明确最大建议缩放；超出后可变糊，但原始笔迹不能受损。
- 网页需要笔迹级别可选择预览与几何，不能仅保存全页图片。PNG是兼容起点，不承诺所有墨水逐笔拼接像素一致；荧光笔组合渲染需原型验证，必要时采用分组/分块缓存+对象映射。不能用“一整块图不可分选”规避N03/N04。
- hitGeometry包含可见轮廓/遮罩后分段近似与界限，不只存中心线或AABB。包含笔宽和原生局部橡皮形成的洞，圈在洞里不选中。须记录近似误差容限与缓存失效策略。
- 预览缓存按资源哈希/墨水参数/导出尺度失效；电脑纯几何变换只更新展示矩阵。需要重新渲染但网页不能生成的原生预览，保留已有可用缓存并在iPad更新；不能用过期预览覆盖源数据。

## 4. 选择、操作与历史（N13–N17）

- **N13 圈选**：闭合套索多边形与可见墨迹相交，或包含其可见部分，则选中整笔；跨圈边笔画整笔选中，不切割。图形使用既有对象选择规则并记录与墨迹的一致性。支持混合选择；锁定对象不参与。
- **N14 变换**：包围盒由实际可见内容求出，拖拽移动整个选择集；缩放控制柄默认等比、绕固定对侧锚点或明确中心。图形与墨迹共用一次世界变换，箭头绑定/文字布局沿用既有规则；一轮拖拽一个历史项。禁止静默变成全页缩放。
- **N15 删除**：Delete/按钮删完整选择集；电脑橡皮扫过可见笔迹删整笔，不能擦到不可见洞而误删。整段是选中若干笔与图形后整体删除。一次橡皮拖动一个事务、一次撤销还原全部。
- **N16 iPad局部橡皮**：使用PencilKit原生能力，结束后更新受影响原生资源、预览、命中几何、ID映射；电脑重开能正确显示擦除结果，并可整笔删除剩余可选择单元。局部擦除后“整笔”按适配层提交的剩余笔迹对象定义，在UI帮助中说明。
- **N17 统一撤销**：图形、墨迹、混合变换、原生笔画与擦除进入同一文档命令历史。不得让PKCanvasView和JS两套撤销竞争。原生编辑作为带前后快照的命令事务交给协调器；Ctrl/Cmd-Z与iPad撤销调用同一入口。cancel回滚，切文档/关闭会话清除旧回调。

## 5. 桥接与文档所有权（N18）

共享文档模型为权威，网页和原生是适配器。建议JS文档协调器管理图形+inkObjects+history，Swift管理本地资源库与PKCanvasView，收到命令确认后更新展示。最终所有权和写入入口在首批ADR固定。

消息含protocolVersion、documentId、sessionId、requestId、baseRevision、类型与payload；显式能力握手、ack/reject、去重、过期revision拒绝。选中集合、工具状态、视口、native edit事务与文件保存都是有类型消息。重载/切文件的迟到消息不能写进当前文档。

不用逐点base64传输，不把巨型drawing反复塞入消息；通过受控本地资源引用/分块方案传送，保存需等待资源与manifest一致。桥仅服务打包受信页面；外链系统打开，不能让任意远程网页调用文件权限。

## 6. 文件打开、保存与兼容（N19–N21）

- **N19** 两端清晰入口：“打开文件”“保存”“另存为/导出可编辑文件”。原生通过系统文档选择器/UIDocument等读写用户选中的本地/iCloud文件，正确使用安全作用域与协调写入。网页支持浏览器能力时保存原文件；否则下载/另存为，并明确不能自动原位保存。
- **N20** 文档修改即时在本地恢复草稿中保存，文件持久化状态单独展示；原生可自动保存打开的文件，失败保留内存/恢复副本并提示。原子写临时文件→成功替换，磁盘满、授权失效、iCloud未下载/离线、取消、外部修改分别处理。不把“本地文件保存成功”叫“iCloud上传完成”。两个设备同时编辑先提示冲突并保存副本，不覆盖另一方，不宣称实时同步。
- **N21** 旧`.excalidraw`正常导入，图形/旧freedraw保持原格式和外观，不假装旧笔迹已原生转换。混合文档默认导出`.lunacanvas`。导出普通`.excalidraw`或PNG/PDF时明确原生笔迹降级为图像的损失，不能覆写唯一混合原文件。网页往返必须保留不理解但支持保留的原生资源。

## 8. 官方依据与依赖原则

查阅日期2026-09-28；Kimi还需按实际Xcode SDK核实可用性，不以网页最新/beta文档代替部署目标支持。

- [PencilKit](https://developer.apple.com/documentation/pencilkit)：原生画布与工具。
- [PKStroke](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct)：路径、变换、mask、renderBounds；不要假定所有新属性可用于旧部署目标。
- [Inspect, modify, and construct PencilKit drawings](https://developer.apple.com/videos/play/wwdc2020/10148/)：公开笔迹模型和渲染。
- [PKDrawing.dataRepresentation](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct/datarepresentation())：原生源数据序列化。
- [UIPencilInteraction](https://developer.apple.com/documentation/uikit/uipencilinteraction)：硬件交互及偏好。
- [UIDocumentBrowserViewController](https://developer.apple.com/documentation/uikit/uidocumentbrowserviewcontroller)：本地/iCloud文件提供者。

默认直接接入官方PencilKit，不为一个薄封装引入整套第三方App。GitHub示例可参考但先审许可证和目标系统，不把项目README当实际验证证据。无付费识别API、无新GitHub仓库要求。
